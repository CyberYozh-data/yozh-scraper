Extraction

i
— disabled — — skip extraction. Use Raw HTML / Screenshot to get the page as-is.
CSS — pull structured data with CSS selectors. Uses lxml.cssselect.
XPath — same but with XPath expressions. More powerful for conditional / positional queries.
Click + Add Field for each piece you want. Every field row takes:
• field name — the key you will see in the response data object (e.g. title, price).
• selector — the CSS / XPath that points at the element (h1, .price_color, //h1).
• attr — what to pull out: text (text content), html (outer HTML), or an attribute name like href / src.
• all — off: first match as a string. On: every match as a list.
Example — real site: scrape app.cyberyozh.com
Fields: page_title=title/text, h1=h1/text →
data = {"page_title": "CyberYozh App", "h1": "..."}
Without extraction the same scrape only returns data: null plus raw HTML you would have to parse yourself.
all example: selector a on a page with 3 links
• off → data.link = "https://a"
• on → data.links = ["https://a","https://b","https://c"]

Custom Headers

i
Extra HTTP headers sent with the request.
Presets fill locale, privacy or navigation headers in one click. They no longer carry User-Agent or sec-ch-ua*: the engine states the only identity its transport can back, so the API drops those from headers and answers with ignored_request_field in warnings. Choose the identity with Engine + Device, and read meta.applied_user_agent for what actually went out.
Interaction with proxy geo: when proxy_geo.country_code is set, the scraper automatically picks a matching Accept-Language (e.g. es-ES,es;q=0.9 for Spain). Your custom headers are merged on top — any header you set here wins, including Accept-Language if you override it. Locale and timezone still follow the proxy geo.
Common additions: Referer, Cookie (prefer the Cookies section), Authorization, site-specific headers.

i
Parallelism — pages inside a single batch run in parallel using asyncio + the scraper's worker pool.
Default: WORKERS=2 browser processes, so up to 2 pages at a time per batch.
To increase: edit the scraper's .env file and bump WORKERS (each browser process uses ~300-500 MB RAM). Then restart the scraper with docker compose down && docker compose up -d.
Note: docker compose restart does not reload .env — use full down/up.

Crawl Parameters

i
Seed URL — the single starting page. The crawler walks outbound <a href> links from there.
Scope — which URLs are followed:
• same-domain: only the exact host of the seed.
• subdomains: the seed's registrable domain + its subdomains.
• all: no domain restriction.
• regex: use Include patterns below. URLs must match at least one include; any match in Exclude patterns always wins.
Max depth / pages — hard caps. max_depth=3, max_pages=500 by default.
Per-domain RPS — requests per second per host. A global token bucket is shared across all running crawl jobs, so two concurrent crawls on the same domain divide the RPS fairly.
Per-domain concurrency — how many in-flight fetches can target the same host from this job. Usually 1.
Enable scraping — when on, each crawled page is kept with its full ScrapeResponse (raw_html/screenshot/extracted data). When off, only URL / parent / depth / status are kept (lighter memory, lighter payload).

Create Session

i
Server-side session: pins a device + proxy and stores Playwright storage_state on the scraper.
Create a session, optionally run a login script to populate cookies / local storage, then reference its session_id on the Scrape Page / Batch / Crawler tabs to scrape authenticated pages.
Credentials passed to the login flow are kept in RAM only and never persisted.

Inject Cookies (paste from browser)

i
Skip the login DSL entirely — log in manually in your real browser, export cookies with an extension like EditThisCookie / Cookie-Editor, paste the JSON here.
Works around CAPTCHA / 2FA / device-verification flows that Phase 1's DSL can't solve. The session then carries your real authenticated state into every scrape.
Accepts EditThisCookie / Cookie-Editor JSON format (with expirationDate) — converted automatically.

Run Login Script

i
Replays a sequence of Playwright actions to populate the session's storage_state (cookies / localStorage).
Reference $creds_email, $creds_password, $creds_totp_secret in step value / url fields — the scraper substitutes them from the credentials below at run time and never logs them.
Define a success selector or success URL regex so the scraper can verify the login actually worked.
